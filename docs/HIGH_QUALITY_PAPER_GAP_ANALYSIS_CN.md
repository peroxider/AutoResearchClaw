# 面向普通模型的高质量 AI 论文 Pipeline：项目缺口分析

审计日期：2026-09-22。代码基线：`f7fe93c`。

实现追踪：逐轮代码与测试证据见 [开发状态](HIGH_QUALITY_PAPER_DEVELOPMENT_STATUS_CN.md)；截至 2026-09-27 的工程范围完成复核与生产边界见 [完成审计](HIGH_QUALITY_PAPER_COMPLETION_AUDIT_CN.md)。本文保留为原始问题基线，不能把后续完成状态反向解释为基线当时已经具备这些能力。

## 1. 结论与审计边界

当前 AutoResearchClaw 已具有完整研究流水线的骨架，适合继续建设，不需要整体推翻。它已经能检索文献、设计并运行实验、修复代码、分段写作、模拟审稿、生成图表和导出论文。但“流程完成”和“达到投稿标准”仍是两个不同的状态：默认降级、弱语义验证、专业分支特化和长上下文依赖，使普通模型的错误仍可能传播到最终产物。

建议产品目标定义为：在指定研究领域、数据质量和计算预算范围内，自动完成可复现研究，生成证据充分、格式合规、可供专家做最终判断的投稿候选稿。选题新颖性、重要性与正确的新理论不能由编排机制保证。证据不足时，应交付明确标记的研究报告或待完善稿；不能把预算耗尽解释为已经达到投稿标准。

本次依据主流程、配置、实验、文献、图表、导出和质量检查代码进行分析；没有调用付费模型运行完整科研任务，也没有完成 GPT-5.6 Luna 的端到端效果评测。不能从通用 API 支持或单元测试推断 Luna 能稳定达到某个录用水平。

验证记录：

- 定向运行 `test_paper_verifier.py`、`test_framework_diagram.py`、`test_medical_paper_quality.py`、`test_reviewer_llm.py`、`test_rc_citation_verify.py`：109 passed、4 skipped。
- 数值归属反例：真实 Baseline=81、Proposed=91；将文字中的两者数值互换后，`verify_paper` 仍为 PASS、strict_violations=0。
- 空新颖性候选反例：`_assess_novelty([], 0.5)` 返回 `(1.0, 'high')`。
- 上述反例验证的是对应组件的缺口，不等于证明每次完整 pipeline 都会产生错误。

## 2. 已有基础与目标差距

| 用户目标 | 当前基础 | 主要缺口 |
|---|---|---|
| 用户数据集 + ideas | topic、extra_prompts、BenchmarkAgent、医学 data_contract | 缺少通用结构化 ResearchBrief、DatasetManifest、输入预检及不可漂移的约束 |
| 可选模板，默认 AI 学术论文 | NeurIPS/ICML/ICLR、部分物理期刊、generic article | 默认仍是 neurips_2025；缺少用户模板导入、规则抽取及期刊/会议双布局 |
| 完整相关工作 | 多源搜索、筛选、知识卡片、引用真实性检查 | 缺少关键论文全文证据、引用句支持检查、覆盖矩阵、检索停止标准 |
| 新颖 highlights | 假设生成、novelty、debate、tournament | 缺少可审计的新颖性对照和贡献—证据绑定；未找到相似论文不能当作高创新 |
| 完整理论与证明 | 理论提示词、领域适配、医学结构检查 | 缺少通用证明义务、引理依赖图、反例搜索和证明状态管理 |
| 公式、伪代码、实现一致 | 代码规格及伪代码提示、AST/实现检查、LaTeX 转换 | 缺少 MethodSpec 统一来源及三方语义一致性验收 |
| 架构图和流程图 | FigureAgent、图像 API、SVG/PNG 混合渲染、matplotlib 兜底 | 缺少通用 DiagramSpec、图型分别验收、图像语义校验及稳定的多后端降级 |
| 实验充分且合理 | baseline/ablation 规划、真实执行、修复、种子统计、CI | 缺少受保护测试集、公平预算、完整矩阵、语义化统计与独立评估器 |
| 充分实验分析 | 图表规划、统计汇总、Results/Discussion 提示 | 缺少研究问题驱动的分析协议、反证/失效分析、图表数据绑定 |
| 引人入胜且闭环的长论文 | 三段生成、多轮检查和修订、审稿模型配置 | 粒度过粗、文本截断、缺少逐项结论追踪及证据驱动的章节契约 |
| 普通模型稳定产出 | 多模型接口、重试、fallback、可选 debate/tournament | 缺少普通模型固定预算基准、最小任务单元、严格结构输出和工具优先验证 |

“SCI”不是一种统一排版模板。建议默认提供通用 AI journal manuscript 结构，明确具体期刊后再适配其版式；会议稿和期刊长稿采用同一研究证据包、不同的篇幅与附录策略。不要把图数、字数、引用数量作为学术质量的替代品。

## 3. 必须优先处理的具体可靠性问题

### P0-A：质量失败仍可继续

代码证据：`researchclaw/config.py:146` 默认 `graceful_degradation=True`；`stage_impls/_review_publish.py:819` 附近低于阈值时可返回 DONE/degraded；`runner.py:806` 附近 pivot 次数耗尽后即使实验质量检查失败仍强制 PROCEED。部分 agent requirements 拒绝在重试耗尽后也转为 proceed，见 `_analysis.py:1087`。

改进：引入 `exploratory`、`research_complete`、`submission_candidate` 等明确产物状态。正式候选稿模式不允许用降级替代证据；错误分类后回退到数据、实验、理论、写作或排版的具体阶段。达到重试/费用上限时保存检查点和缺项清单，不擅自标记完成。

验收：低分、未完成关键实验、未知证明状态、未验证关键引用均不能获得 submission_candidate；仍可导出带状态的诊断材料。

### P0-B：数字出现过不等于归属正确

代码证据：`verified_registry.py:69` 的全局数值字典，以及 `:117` 的容差匹配。`paper_verifier.py` 调用该匹配检查数字。该机制能发现很多凭空数字，但互换方法结果的反例仍通过。

改进：把 Numeric Whitelist 升级为 EvidenceStore，主键至少包含 dataset/version/split/method/config/seed/metric/aggregation。保存原始预测或输出、代码提交、环境、执行记录和派生计算。表格和数字由结果 ID 渲染，LLM 只负责解释。差值、提升率、排名也通过可执行表达式生成并绑定来源。

验收：方法互换、数据集互换、AUROC 当 accuracy、百分比与百分点混用、旧版本结果混入、失败 run 冒充成功 run 都必须被拒绝。执行环境真实运行不自动证明研究正确；可信评估器必须独立计算主要指标，生成方法的模型不能同时任意改写评估逻辑。

### P0-C：统计实现包含需要修复的语义风险

代码证据：`_analysis.py:333` 识别 condition/regime/seed/metric，但聚合只保留 condition 与 seed；同一 condition 的不同 regime 复用 seed 时存在覆盖风险。`:409` 以字母序第一项作为比较基线。`:421` 将差值标准差为零时的 t 统计量设为 0，需要区分完全相同与非零常量差值等退化情况。`_paper_writing.py:1433` 的消融检查根据结果相似度推断消融失效，`_analysis.py:1236` 将此注入 REFINE。

改进：采用完整实验主键和预声明比较关系；由明确的统计协议选择配对检验、非参数检验或 bootstrap；保留重采样单位、效应量、区间、多重比较策略。随机种子、交叉验证折、样本和数据集不是可以随意合并的独立重复。没有显著提升或移除组件后无变化可能是真实科学结论，不应单凭结果接近认定实现错误。

验收：跨 regime 不覆盖；交换方法名称不改变基线选择；常量差值处理明确；消融必须通过实现/执行轨迹证明组件确实移除，效果弱时如实报告。

### P0-D：引用检查并非最终的严格通过门

代码证据：`_review_publish.py:2930` 附近无 bib 时写 integrity_score=1.0 并返回 DONE；阶段尾部校验/过滤后仍返回 DONE；`:2995` 固定 MAX_CITATIONS=60。对于需要充分相关工作的长稿，这个统一上限并不适合所有目标。

改进：区分 missing、unavailable、verified、contradicted，不把没有引用当作验证成功。引用分别检查“存在”“元数据正确”“支持该句”“覆盖必要工作”；剔除引用后重写受影响论断，并重新运行最终整稿检查。上限应来自目标版式与相关性，不应全局硬编码。

验收：不存在的引用、真实但不支持陈述的引用、删除关键引用后失去依据的结论均不可获得正式通过。检索故障不能产生“文献完整”的结果。

### P0-E：最终版本缺少一次完整、不可绕过的验收

代码证据：Stage 20 在导出改写、数字清理和 Stage 23 引用处理之前。Stage 22 编译发生在框架图生成之前（`_review_publish.py:2549` 与 `:2779`）；runner 打包时会再编译，但失败/跳过为非阻塞。`_review_compiled_pdf` 实际读取前 12000 字符 LaTeX，而非查看 PDF 页图，见 `_paper_writing.py:1329`。打包中还有保留已清理 TeX 而跳过 verified Markdown 再生成的路径。

改进：建立单一 Manuscript AST/IR，MD、TeX、PDF、Bib、图表从同一版本生成。完成全部数值、引用和图表修订后，再进行编译、逐页布局检查和全量证据复核；任何后续改写使原审核失效。最终 manifest 绑定文件哈希、证据版本和审核版本。

验收：PDF/TeX/MD 的核心数字、引用、图表一致；缺图、断引用、页数违规、占位符、编译失败不能通过正式验收。清理成 `---` 的结果不是问题已经解决。

## 4. 研究输入与数据能力

建议增加 `ResearchBrief` 和 `DatasetManifest`，把用户输入从长提示词变为受校验的对象：研究问题、idea 列表、不可更改的约束、可调整假设、目标论文类型、数据路径、标签、禁止特征、分组/时间字段、任务指标、计算/API 预算、是否允许外部数据。

数据接入应完成：文件可读性与 schema、数据指纹、重复/缺失/异常分布、标签统计、实体重叠、标签泄漏、预处理 fit 范围、分层/分组/时间切分；产出 dataset card、EDA 图表、固定 split IDs 和数据来源说明。涉及任务决策的探索与变换应遵守测试集隔离。

医学分支已有冻结 contract 的好基础，但从 extra_prompts 提取路径及专用 executor 配置的模式，应抽象成全领域数据契约，避免仅靠模型从文字推断。`scripts/analyze_paper5_dataset.py` 等单篇脚本也应沉淀为可配置分析组件，而非每次新题目再写一套。

外部数据扩展需提供 UCI/OpenML/Hugging Face 等适配器、版本/哈希、许可证和引用、缓存/重试/下载校验、任务语义兼容检查。BenchmarkAgent 已有本地知识库和 HF 搜索，应该扩展它，而不是重新搭建一套。

UCI 适合某些表格学习和方法验证，但并非任何 AI 论文的充分证据。按声明选择小规模快速验证、领域主 benchmark、外部泛化数据；不能因为数据容易获取就自动拼接成“实验充分”。UCI 官方也要求具体数据集采用各自的引用信息：[UCI citation guidance](https://www.archive.ics.uci.edu/citation)。

## 5. 文献与创新能力

需要从“收集相关标题/摘要”提升为“形成可检查的研究定位”。现有 Stage 6 主要消费 shortlist 和有限 web context，存在抽取失败后的模板卡片路径；虽然有 PDF 提取等工具，但关键论断没有强制绑定全文出处。

建议产物：

1. `literature_coverage_matrix`：主题、基础方法、直接竞争工作、近期进展、数据集/评价协议。
2. `evidence_cards`：原文段落/页码、论文 ID、适用条件、支持/不支持的陈述、阅读范围。
3. `novelty_matrix`：每项 idea 与最接近工作的差异，是新的假设、目标函数、模块、证明、应用条件，还是命名变化。
4. `contribution_ledger`：每条 highlight 对应文献差异、理论命题或实验比较及失败条件。

检索应记录数据库、查询、时间和前后向引用扩展，并有覆盖不足的停止/补搜机制。无法保证“引用穷尽”，但可以使“哪些方面充分、哪些方面仍未知”可审计。`novelty.py:369` 的空候选高分需改为 unknown，并保留检索成功/失败状态。

普通模型应先提出多个有限候选，经过可执行最小实验与最接近工作对照后再选择；多轮自评本身不能创造独立证据。发现 idea 已有、优势不成立或数据不支持时应修改主张或停止，而非通过文字包装制造新颖性。

## 6. 理论、算法与实现的一致性

建议新增 Theory Workbench：定义/符号表、假设清单、命题、引理依赖、逐步证明、引用定理的适用条件、边界情形、反例搜索和证明状态。

普通模型每次只处理一个证明义务，工具辅助符号等式、量纲、梯度、小规模穷举或数值反例检查；适合的核心定理可选择形式化验证。数值检查通过不是数学证明，模型审稿通过也不是形式证明，应区分 `machine_checked`、`reviewed_informal`、`unresolved` 等状态。

当前医学检查主要搜索 proposition/theorem/lemma、proof/argument 和数学块数量，是结构检查，不能证明推导正确。用户要求理论贡献时，无法完成关键证明必须显式保留缺项；如果研究本质是实证贡献，可协商论文类型或给出诚实的分析，不能为了格式硬凑无关定理。

新增 `MethodSpec` 作为公式、伪代码、代码和图的共同来源：输入输出、张量形状、损失函数、更新规则、训练/推理分离、停止条件、时间空间复杂度、关键模块到代码符号的映射。使用维度检查、微型实例、梯度检查和模块关闭测试，验证实现是否对应论文中提出的方法。

## 7. 实验与分析能力

现有基线、消融、修复、多种子、CI 值得保留；问题在于它们尚未形成按研究主张强制完成的协议。默认实验预算 300 秒、repair 最少两种 condition/50% 完成率，不宜作为充分科研证据的默认解释。Stage 9 为适配预算会裁剪 conditions，必须同步降低主张或声明待补证据。

建议研究矩阵由以下维度构成，而非简单给每篇论文相同数量：数据集 × 方法 × 公平调参预算 × seed/fold × 实验问题。

- 主比较：简单强基线、最接近方法、适用的近期方法，共同 split、预处理与选择准则。
- 消融：核心模块独立关闭、关键组合、机制假设对应的观察指标。
- 敏感性：关键超参数与数据规模/噪声/缺失等任务相关条件。
- 泛化与失效：适用时加入跨域、分布漂移、外部集、失败案例及不适用区域。
- 效率：训练/推理时间、内存、参数量或 API 成本，注明硬件与测量协议。
- 统计：效应量和不确定性优先，检验方法与比较单位明确；多 seeds 并不自动代表样本量充分。

将探索集/验证集和最终测试集隔离。模型选择、repair、tournament 的成功判据不能反复窥探最终测试结果；所有候选与失败实验保留，避免只挑有利运行。最终采用冻结配置及独立评估器验证。

每个研究问题生成 `AnalysisSpec`：使用哪些结果 ID、计算什么统计量、绘制何种图、能推出和不能推出什么。图表应由真实数据与可保存脚本生成。可按任务选择主结果 CI 图、消融图、敏感性、学习曲线、效率 Pareto、校准、误差分组与案例图；没有数据支持的图不为了凑数生成。

## 8. 图像生成：已有支持，但通用语义仍不足

当前 `framework_diagram.py` 已支持多个图像 API、传统渲染和混合模式，配置默认 `render_mode=hybrid`。混合模式把确定性 SVG/PNG 层作为节点、标签、箭头的来源，图像模型的影响仅为很弱的视觉层。这与“图像模型主生成，其他方案兜底”的偏好不完全相同。

特别需要处理：`_semantic_framework_nodes` 中存在 Clinical Record、Outcome-Blind Scrub 等预设医学节点；`generate_framework_diagram_artifacts` 对 trace-guard 有专门分支。确定性渲染可以锁住既定语义，但若语义提取本身有误，锁定也不能使其正确。

建议通用 DiagramSpec 至少包括 nodes、ports、edges、edge types、training/inference、grouping、labels、equation refs、source MethodSpec version。按用户需求分别定义：

- Introduction 的问题/输入—方法—输出概览图。
- Methods 的模块架构图。
- 算法的执行流程图，体现分支、循环、终止条件。
- 必要时单独展示实验协议/数据分割，避免与算法路径混淆。

生成路径：DiagramSpec → 图像模型主生成 → 标签/箭头/拓扑及版式检查 → 局部修改 → 仍不合格时 Mermaid/SVG/Graphviz/TikZ 或 HTML 渲染 → 统一导出与整稿检查。保留模型、prompt、原始输出、规范和哈希。图中公式、重要文字可采用矢量覆盖，确保出版缩放后清楚。

没有可用视觉验证能力时，应标记自动语义校验的能力边界，或采用受控矢量方案；只做 OCR 不能完全验证箭头关系。统计图继续用程序绘制，保证数值可追踪。切换到已有 direct 模式只改变图像生成方式，不能自动补齐上述质量保障。

## 9. 详实写作、模板与讨论闭环

`_write_paper_sections` 已分三次生成，但一次仍包括多个大章节，并大量依赖字数和引用数提示。通用质量 gate 截取约 40000 字符，PDF review 函数只取前 12000 字符 TeX，长稿后半部分可能没有充分检查。

应按 section/subsection 分解，每个写作任务提供固定证据包：研究问题、可用 claims、引用片段、符号表、对应结果表、图表以及禁止外推边界。先写方法/实验/结果/理论，最后重写 introduction、abstract、highlights 与 conclusion，以最终证据闭环。

写作验收示例：

- Introduction：问题为何重要 → 已有方法的具体缺口 → 本文如何填补 → 每项贡献由什么证据支持。
- Related Work：比较机制、假设和适用条件，避免逐篇摘要堆叠。
- Methods：符号、假设、公式、伪代码、实现、复杂度一致。
- Results：每个 RQ 有实验、图表、量化观察、统计不确定性及解释。
- Discussion：机制证据、替代解释、失败情形、适用边界、成本权衡；不能把猜想写成已证结论。
- Conclusion：只回收已验证贡献，准确限定条件，不引入新结果。

模板能力应支持用户给出的 LaTeX 模板包，解析文档类、引用风格、页数、匿名要求、附录与图表规则。没有模板时使用通用 journal manuscript；明确会议目标后压缩主文，把证明、补充实验和实现细节放入附录。单独 highlights 文件是否生成取决于目标期刊要求，但贡献记录应始终存在。

## 10. 普通模型适配方案

不应以更换强模型作为质量方案的前提。可以用同一个普通模型运行不同角色，但角色数量增加不代表判断独立。关键是让普通模型解决更小、证据更完整、输出可检查的问题。

| 机制 | 实施方式 | 主要收益 |
|---|---|---|
| 小任务单元 | 单个证据卡、命题、实验条件、函数、图或小节 | 降低遗漏和长上下文漂移 |
| 结构化产物 | JSON Schema + 字段/跨字段规则 + 有界修复 | 让缺项立即可见 |
| 证据包检索 | 按任务读取对应数据/论文片段/代码及完整元数据 | 少依赖模型记忆和跨阶段摘要 |
| 工具优先 | 指标计算、统计、绘图、LaTeX、代码检查交给程序 | 减少模型计算错误 |
| 隔离评审 | 新上下文先查看原始证据，要求定位问题和提出反例 | 减少作者解释诱导，但不宣称完全独立 |
| 候选筛选 | 以可执行实验、约束和外部证据选候选 | 减少纯主观评分投机 |
| 定向回退 | 每条 issue 携带 artifact、checker、repair owner | 修复真正原因，避免只润色 |
| 状态与缓存 | typed DAG、内容哈希、依赖失效和运行恢复 | 修改一个结果后重建所有受影响段落和图表 |
| 预算管理 | 先试运行估时，再完整实验；按证据价值分配预算 | 不为完成流程牺牲关键比较 |

现有 23 阶段可保留为用户可见进度；内部逐步改为有类型的依赖图。ResearchBrief、DatasetManifest、MethodSpec、ExperimentProtocol、EvidenceStore、TheoryBundle、DiagramSpec、ManuscriptIR 是建议新增/扩展的架构产物名，不是当前已经存在的功能。

固定普通模型测试应记录实际 model ID、端点、参数、预算和回退情况；不默认其显示名称就是可直接调用的 API ID。评估时关闭未声明的强模型回退，图像模型作为单独允许的能力记录。

## 11. 建议实施顺序与验收

| 阶段 | 工作范围 | 完成标准 |
|---|---|---|
| P0 可靠性底座 | 质量状态、EvidenceStore、统计 bug、引用 gate、最终版本验收 | 错误归属/失败 gate/缺引用/缺图/过期结果的反例被拦截 |
| P1 数据与实验通用化 | ResearchBrief、数据预检、固定 split、UCI 等适配、公平基线/消融、可信评估器 | 用户数据能稳定接入；所有核心实验有真实可复算结果 |
| P1 研究内容 | 全文证据和 novelty/contribution matrix、TheoryBundle、MethodSpec | 核心主张逐项有证据；理论和实现的未决问题可定位 |
| P1 写作与图像 | 小节契约、图像优先生成及矢量兜底、模板导入、最终 PDF 验收 | 详实稿在正文、附录、图表和引用间闭环 |
| P2 普通模型基准 | ARC-Bench 扩展、固定预算、故障注入、盲评和独立复现 | 可报告普通模型端到端成功率、错误接受率、成本与人类修订负担 |

质量等级建议不要由一个总分覆盖。数据、实验、数值、引用、证明、图像、排版都应有独立状态；任一关键项失败都不能由写作高分抵消。

新基准应至少覆盖：表格分类/回归、时序或图像任务、数据泄漏陷阱、无效 idea、真实零提升/负结果、外部下载失败、错误证明、图像 API 故障、缺模板和长论文。每类任务多次重复；金标准与验收用例避免被调优流程直接利用。

应记录的指标包括：关键 claim 证据绑定完整率、错误声明漏检率、引用存在率与支持率、必需实验完成率、独立复算一致性、理论未决项、图表语义错误、最终文档一致性、运行成本/时间、人工修订量。某些安全性指标可设“已检出关键错误零放行”的验收要求，但不能把有限测试上的 100% 解释为任意论文的绝对保证。

现有 ARC-Bench 包含 55 个题目和相应基础设施；README 明确完整论文质量 meta-rubric 是手动审计路径，公开树主要提供输入。它适合作为新基准的基础，但不是现成的 Luna 高质量论文能力证明。

## 12. 外部标准对照

NeurIPS 的官方 checklist 强调 claims 与证据一致、理论假设与完整证明、实验复现、统计不确定性等，而不是要求每篇论文都堆满所有形式元素：[Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)。因此验收应围绕正确性和证据覆盖建立，不围绕篇幅及图表数量建立。

最终期望是让模型主要承担有依据的研究建议、代码实现和表达工作；把数据来源、实验协议、计算、版本、证据一致性和交付条件放进系统的可验证机制。如此可以显著提高普通模型的可靠性，但仍应以实际基准和专家评估决定它能承担的研究难度。
