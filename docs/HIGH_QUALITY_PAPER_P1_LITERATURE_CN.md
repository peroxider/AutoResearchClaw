# P1 文献证据、贡献记录与逐处引用核验

本轮实现来源快照 → 证据卡 → 覆盖报告 → 新颖性对照 → 贡献记录 → 逐处引用核验。正式研究在证据不足时停下；模型评分不能补齐缺失来源，也不能证明原创性。入口在 Stage 4、6、8、14、23，最终交付重新校验版本与依赖。

## 输入与配置

可在运行目录放置 `literature_input/sources.json`，文件路径相对于该目录：

```json
{
  "schema_version": 1,
  "papers": [{
    "cite_key": "smith2024method",
    "title": "用户提供的准确论文标题",
    "authors": ["作者姓名"],
    "year": 2024,
    "url": "https://example.org/paper",
    "path": "paper.pdf"
  }]
}
```

支持 PDF、UTF-8 TXT/Markdown；拒绝目录外路径与重复引用键。不会读取模型自行建议的任意本地路径。Stage 4 同时保留真实检索候选、本地来源的书目信息及可用的网页 PDF 抽取；远程检索成功时本地条目也会进入参考文献表。书目元数据是否真实仍需 Stage 23 核验。

```yaml
literature_search:
  evidence_mode: auto
  evidence_max_papers: 12
  evidence_max_calls: 32
  evidence_max_chars: 12000
  citation_support_max_calls: 128
```

`auto` 在正式目标、结构化 brief、可用全文或本地文献输入时启用；`on` 强制启用；`off` 保留旧提取路径，但不能绕过最终的证据门禁。预算按阶段调用计数，包含失败调用；当前不是整个运行的 API 成本账本。每篇最多提取两张卡，最多读取四个分散页面的有界窗口；不宣称模型阅读了整篇论文。

## 证据与状态

- `literature_evidence.json` 保存来源身份、PDF 原件摘要、实际页数、每页/文本片段快照、字符定位、精确摘录、提取窗口及隔离上下文的语义评审。
- `evidence_artifacts/literature_sources/` 采用内容寻址，更新来源不会覆盖旧文本。刷新前的证据及下游报告归档到 `literature_history/`，下游状态立即失效。
- `scope` 区分全文、摘要和不可用；`retrieval_scope` 区分取得完整文档与部分/未知抽取。PDF 页数和实际抽取页数不一致时不能算完整取得。
- 原文中能找到摘录，只证明摘录出处。`supported` 还需要单独检查方向、条件、数值、因果和限制的语义评审。无评审、调用失败、预算耗尽均为未知。
- `literature_coverage.json` 按主题、基础工作、直接竞争者、近期工作和数据/协议分类；只有来源完整取得且语义评审支持的卡进入覆盖。检索记录也必须成功，才可标记 `review_ready`。类别由提取模型提出，此状态只表示可以进入评审，`exhaustive` 始终为 false。

网页抽取按来源 URL/arXiv 身份匹配，不按相似标题拼接。原始快照保留在交付证据目录中；配置的语言模型会收到相应有界原文窗口。哈希用于完整性和版本绑定，不是来源真实性签名。隔离上下文允许复用同一普通模型，不能称为统计独立或专家证明。

## 新颖性与贡献

Stage 8 的 `novelty_matrix.json` 对每个 idea 保存稳定身份、实际检查的最多八张近邻卡、未检查的卡以及原始评审。输入 idea、证据集合或评审结论改变都会使绑定失效。没有候选或评审不能给出“高新颖性”；仅重命名或未知差异保持 `unresolved`。`candidate_difference` 仅为有条件的差异候选，`novelty_guaranteed` 永远为 false。

Stage 14 的 `contribution_ledger.json` 从冻结协议及 EvidenceStore 重算比较，把 RQ、数据、指标、基线、候选和每个种子的结果 ID 绑定起来；明确报告零差异和负结果。缺失任意必需配对使观察未决，不选择性忽略失败种子。当前范围是固定测试切分上匹配训练种子的观察，不推出总体显著性。TheoryBundle 义务状态原样保留；非形式化证明不会升级为机器证明。

写作上下文读取前会验证上述产物。最终验收独立重算贡献记录，拒绝过期数值、来源或理论版本。当前仍需 ManuscriptIR 将每项正文贡献与这些记录逐项绑定；存在 ledger 不等于所有文字已经得到支持。

## 每次引用的核验

`citation_support.json` v2 分别绑定 Markdown 和 TeX 的文件摘要、引用出现位置、完整相邻主张、同篇论文的证据卡/片段以及原始评审。重复引用不会合并成一个通过状态；同一键的一处有依据，不能授权另一处无关结论。行内引用后面的谓语也进入待评审主张。

Stage 23 使用最终阶段的 Markdown 和 TeX 逐处检查；正式目标需要元数据与主张支持都通过。缺失文件、未覆盖引用、摘要冒充全文、预算耗尽、矛盾评审和文件变化均不能通过。旧 v1 专家条目仅覆盖紧接其原文主张的引用，不能按键放行整稿。

最终打包后继续检查文件摘要；打包过程若改写正文，旧评审自然失效。共同 ManuscriptIR 导出和对最终字节的重新核验闭环仍在后续开发范围。当前引用句定位是 Markdown/TeX 词法与句子边界规则，并非完整排版 AST；复杂公式、表格、脚注需要后续结构化契约支持。

## 测试与剩余范围

测试覆盖精确摘录但不支持结论、来源/位置/评审篡改、部分 PDF、摘要冒充全文、服务失败、调用上限、重复引用的矛盾结论、过期正文、新颖性输入错绑、零提升及缺失种子、本地/远程参考文献共存。真实生成的两页 PDF 验证分页抽取和文件摘要；语义结论使用可控假评审器，不能作为真实研究质量验证。

尚未实现按覆盖缺口自动补搜循环、每个检索提供方/查询的独立成功凭据、领域自适应类别及有理由的“不适用”声明。当前记录聚合检索状态、暴露缺口并暂停正式流程。没有执行真实付费模型或整篇论文端到端验证。
