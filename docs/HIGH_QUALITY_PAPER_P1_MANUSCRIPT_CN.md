# P1 章节证据契约与 ManuscriptIR

本轮把结构化研究的写作路径改为：证据目录 → 小节任务 → 段落与小节评审 → ManuscriptIR → 共源 Markdown/TeX → 最终一致性验收。模型评审是有记录、可失效的判断，不是科研结论正确性的形式证明。

## 启用与阶段

Stage 17 在 `target_status` 为正式目标或存在 `research_contract.json` 时启用结构化写作。已有 `manuscript_ir.json` 的运行在 Stage 18/19/20/22 和打包阶段继续使用该路径。无结构化输入的探索性运行仍保留旧写作路径；正式路径缺证据时不回退到自由生成稿件。

- Stage 17 按 methods、experiments、results、可选 theory、related work、discussion、introduction、abstract、conclusion 的顺序组织写作任务，先写研究内容再写概括性章节。
- Results 根据冻结协议的每个 RQ 及 contribution ledger 中的比较组织小节；其他章节对超过单包容量的证据拆成多组，禁止截掉尾部。
- 每个段落声明 `evidence_ids` 和主张类型，全文交给新上下文核验。每个小节还按职责契约评估完整性、解释深度及边界。解释、限制和假说会显示明确标签，标签不豁免其事实前提的检查。
- Stage 18 再次逐段、逐小节进行完整同行评审，不只读取长稿前部；结果包含输入稿件版本及逐处问题。
- Stage 19 把审稿反馈绑定到新一轮小节任务。当前反馈作用于全部小节；精确到单个 issue 的最小重写仍是后续工作。
- Stage 20 取所有小节分数的最小值，并要求全部契约和段落评审通过。长稿某一节失败不能由其他高分平均掉；同时检查阶段 Markdown 与 IR 一致。
- Stage 22 使用确定性渲染器导出。Stage 23 不在 IR 外删除正文引用或改写科学主张；失败引用进入修复/验收问题。

## 证据与版本

`evidence_catalog()` 从冻结 brief、MethodSpec、TheoryBundle、ExperimentProtocol、EvidenceStore、全文文献卡、novelty matrix 和 contribution ledger 重新构建上下文。使用前检查文件/内容摘要、结果原始产物以及各自模块的契约；不会给写作模型提供测试标签或测试数据行。

每个段落保存完整文本、主张类型、明确证据集合、评审原始响应和请求摘要。小节保存职责、全部必需证据、写作/修复尝试、质量评审。修改段落、idea、结果、来源、标题或职责后，即使重新计算外层 JSON 摘要，也不能复用旧评审输入绑定。

运行目录中的 `manuscript_ir.json` 每完成一项任务就保存。仅在所有来源、任务、提示和反馈完全一致时，恢复执行会复用已通过的小节；旧稿归档到 `evidence_artifacts/manuscript_history/`。未完成任务保持 `incomplete`，不能获得正式导出。

## 预算与失败

```yaml
research:
  manuscript_max_calls: 160
```

这是每次草稿、修订、同行评审阶段的调用上限，包含失败调用，不是全项目 API 成本上限。单小节默认最多一次修复。普通小节证据包最多八项；RQ 结果小节包含对应贡献记录和分组结果。单段最多 6000 字符，小节最多 12000 字符，单证据包超过 80000 字符时要求拆分源契约，不进行静默截断。服务缺失、预算耗尽、评审未知或遗漏必需证据都会暴露为未完成状态。

## 共源导出与交付

数值表由 EvidenceStore 生成。相同 dataset/version/split/metric/aggregation/regime/unit 的记录合并为比较表，行包含 method、configuration、seed 和 value。表注显示完整条件和配置标识；配置只使用表内 C1/C2 等序号映射，完整原值同时显示，不截取哈希前缀。身份字段因此仍完整保留，不会把不同条件的数值误合并。

相同 RQ 的连续写作证据包先合并，再按每表最多 12 行、4 个配置分表，不丢弃尾部，也不把写作包边界暴露成重复小表。单栏使用带重复表头/条件的 longtable，双栏使用带正文引用的 table*；方法图和结果图表在对应章节末尾设置 FloatBarrier。生成段落使用局部首尾孤行控制，不修改模板字体。特别长的标识、复杂图或严格期刊版式仍需实际整稿检查。

`numeric_claims.json` 由渲染器生成，保存完整结果键、单位、源结果 ID、表号、行号、配置别名，以及两个格式中的精确数值位置。最终重新渲染会校验全部绑定，模型不能通过互换方法标签来复用同一个数字。标识采用等宽字体，避免 PDF 字体连字改变复制出的配置哈希或方法名。零差异和负数保持原有来源和六位小数规则，不进行排名美化。模型撰写的解释仍需逐段语义核验；不把正则表达式当成通用科学数值理解器。

`manuscript_bindings.json` 保存段落在 Markdown 和 TeX 中的位置、证据集合及 IR 版本。最终验收从权威证据重新渲染并逐字比较两个文件；修改、漏段或额外结论都会失效。引用由段落绑定的文献卡生成，并继续接受 Stage 23 的逐处来源核验。

后续新增 [AnalysisSpec](HIGH_QUALITY_PAPER_P1_ANALYSIS_CN.md) 作为稿件依赖。匹配的 RQ 结果任务同时获得冻结分析方案、完整配对来源、重算统计量及解释边界；概括章节可访问这些分析证据。分析原始输入或规范变化会失效相应写作评审，不能仅修改外层摘要继续使用旧稿。

结构化打包复制已完成阶段的准确文件，绕过旧的再生成、自动润色和引用替换步骤。编译器新增 `allow_repairs=False`，用于该路径时不进行 Unicode/BibTeX 清洗或 TeX 自动修复；编译问题需回到源产物修复，不能在已评审稿之外悄悄改字。

## 验证与边界

测试覆盖全结果导出及精确数值位置、错引用/漏证据、评审矛盾、预算恢复、证据变更后的缓存失效、重新摘要后的文本/证据/标题篡改、八万字符以上长稿尾部评审、单节低分、阶段集成、打包一致性和禁止编译改写。测试中的语义模型是可控假实现，只证明流程和拒绝条件，不能证明实际模型判断准确率。

当前默认导出通用 journal 稿件，也支持 [本地模板导入](HIGH_QUALITY_PAPER_P1_TEMPLATES_CN.md)、附录角色和按需 highlights；复杂模板/Biber 与期刊特有规则仍未全部支持。MethodSpec 公式/算法步骤、TheoryBundle 证明记录及配对结果图见 [出版资产说明](HIGH_QUALITY_PAPER_P1_ASSETS_CN.md)。算法分支/循环和通用 DiagramSpec 已有基础实现，见 [图说明](HIGH_QUALITY_PAPER_P1_DIAGRAMS_CN.md)；专业统计图表、复杂图分页及精确 issue 定向修订仍待开发。

后续已安装临时便携 TeX，完成 pdflatex/xelatex 的单/双栏工程样稿编译、最小投稿包解压重建和整稿页面检查，见 [投稿与编译说明](HIGH_QUALITY_PAPER_P1_SUBMISSION_CN.md)。最终验收继续保留未知/失败的实际稿件排版与图像维度，不将工程 fixture 或文本一致性通过视为完整投稿候选稿。未运行真实付费模型整篇论文生成。
